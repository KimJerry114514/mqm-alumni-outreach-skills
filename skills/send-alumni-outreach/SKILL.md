# 校友邀约发送与状态记录

使用属于当前作者、已经批准的 Email Content，配合本人发件账号和签名发信，并记录实际发送状态。文案生成使用 draft-alumni-outreach；本 skill 不重新拟稿或收集邮箱。

## 首次使用与发件人核对

先读[当前用户资料与首次使用](../draft-alumni-outreach/references/user-setup.md)。缺少该参考文件时，仍须按本节核对当前作者和发件账号，不能默认原作者身份。

- 复用本轮已确定的表格路径（.xlsx 或 .csv）、sheet 和当前作者资料。缺少路径时先收集并列出 sheet；已有信息不重复问。
- 发送前核对原稿的作者姓名、经历与当前用户简历/已核对资料一致，实际发件账号（Outlook、Gmail 或其他已连接客户端）和所选签名属于该作者。尚未指定签名时只补问本人签名名称或内容，不猜默认值。
- 新用户无需原作者简历、测试邮箱或签名。换简历人物不能继承原作者已打开邮箱、批准或发送记录；测试收件地址必须由本轮用户指定。
- 若正文仍是另一作者的自我介绍，先回写稿阶段处理，不边发送边换名字。若发件账号属于其他人，先核对用户是否明确授权合法代发及真实身份表达，不能直接把他人简历当成本人身份发送。
- 旧 Sent Email / Sent LinkedIn 或旧日志需要核对发件人归属；归属冲突只问影响发送的一项，不清空旧标记、不把另一人的“已发”自动认作本人已发。
- 不要求重复上传简历：已有属于本人的可靠资料和已批准原稿时可复用；只创建技能或提供简历不构成发送授权。

## 范围与发送授权

- 读取当前工作簿并列出实际 sheet；用户已指定时直接采用，否则询问使用哪个 sheet。
- 默认只处理该 sheet 当前筛选可见的有效人员行，不再询问范围；每次重新核对实际隐藏状态。明确指定其他范围时遵从本次要求。
- 发信需要本次明确授权。用户已批准本轮真实收件人、内容与范围时，直接执行，不重复索要确认。只请求创建 skill、填文案、预览或测试不授权正式发送。
- 用户说先测试时只发指定测试邮箱，完成测试后等待其反馈；测试成功不自动启动正式批次。
- LinkedIn 私信由用户手动发送。本 skill 不点击 LinkedIn 发送、连接申请或尝试规避限流；只维护文案和已确认的手动发送状态。

## 列与状态

按实际表头唯一定位姓名、Email、LinkedIn、Email Content、LinkedIn Message 和状态列，忽略大小写与首尾空格。

- 邮件状态复用 Sent Email；兼容现有 Send Email。
- LinkedIn 状态复用 Sent LinkedIn；兼容 Send LinkedIn / LinkedIn Sent。
- 存在唯一兼容列时不要新建同义列；有歧义时只询问必要的列映射。
- 状态列缺失时，在现有表末补上缺少的 Sent Email / Sent LinkedIn，不移动或覆盖原列。沿用相邻表头格式，保证表头可读。
- 确认发送成功后填数值 1。未发送、跳过、测试、失败或结果不明确时留原值，不写 0、不清空已有标记。
- Sent Email 已为 1 的行跳过，避免重复发送。其他非空状态按其实际含义处理；无法确定时暂缓该行，不覆盖公式。
- LinkedIn 状态只根据用户明确告知的已发送对象/行或可靠的现有记录填 1；有文案、有邮箱或邮件已发送均不代表 LinkedIn 已发送。

## 邮件资格与原稿

仅发送满足全部条件的人员行：

1. 当前获准范围内，未确认发送。
2. Email 为合法且已核对归属的普通邮箱。
3. Email Content 有已批准的主题与完整正文，不是公式、状态文字或内部批注。
4. 姓名、称呼、收件地址和原稿属于同一人；身份冲突未解决时暂缓。

教育或校友邮箱不发送，包括教育邮箱/校友邮箱/校友邮件等文字标记，.edu、.edu.cn、.ac.uk 及已确认的学校和专用校友机构域名。地址格式正确不代表可投递。邮箱类型不明时暂缓，不猜测。

- 使用当前单元格原稿。格式为 Subject: <主题>、空行、完整正文时，将主题与正文拆开；正文不带 Subject 行。
- 保留称呼、段落和原 Best, / 当前作者本人姓名的落款，不擅自改写已批准内容。
- 一个对象一封，To 仅为该行邮箱，不添加未授权的 CC/BCC、附件或其他联系人。
- 同一邮箱/人员重复出现时核对并去重，不重复发送；日志保留重复行关联。
- 核对作者归属后的已有发送标记及可用的已发送记录用于排除重复。没有标记但存在完全匹配的正式发送证据时，记录并补标，不重发。不能把发给用户个人邮箱的测试记录当作已发给校友。

## 发件账号与签名：先问再选发送方式

默认发件账号是用户本人的学校 Outlook 邮箱（教育邮箱，例如 Microsoft 365 / Outlook 网页版）。这是**发件人**；收件人一侧「教育/校友邮箱不发」的规则不变。用户明确要用其他本人邮箱时遵从。

发送前先问一次（已在本人配置中记录且未变化时不重复问）：

> 发出的邮件需要带你在 Outlook 里保存的签名吗？
> 1. 需要带签名（含图片、链接或格式）：我会在你已登录的 Outlook 网页里逐封发送，速度较慢，但签名和你平时手动发的一样。
> 2. 不需要，或只在 Best, 落款后加几行文字：我用邮件连接器直接发，速度快。

| 选择 | 发送方式 | 要点 |
| --- | --- | --- |
| 1. 带已保存签名 | 浏览器操作用户已登录的 Outlook 网页，逐封新建、插入签名、发送 | 复用用户已登录的浏览器会话；按下列签名核对步骤逐封进行。慢，但签名一致。 |
| 2. 不带签名 / 纯文字签名 | 当前环境中可用、且登录的是用户本人发件账号的邮件 MCP/连接器（如 Outlook / Microsoft 365；用户确认后也可用其本人的 Gmail） | 先核对连接器实际登录的账号就是用户指定的发件地址，不一致时停止并告知。纯文字签名追加在 Best, 与姓名之后。连接器只能发纯文本时不得声称附带了 Outlook 签名。 |

- 连接器不可用或账号不符时，告诉用户可改用方式 1，或先在本机连接自己的邮箱，不改用他人账号代发。
- 任何方式都不从浏览器或客户端提取密码、cookie、token；独立 API 需要用户本人合法授权。
- 用户选定的方式和签名设置保存到本人外部配置（`mail.from_address`、`mail.signature_mode`: `outlook_saved` / `plain_text` / `none`、`mail.signature_text`），下次只确认、不重问。

### 方式 1 的签名核对

- 从当前作者独立外部配置或本轮明确输入读取本人发件账号和签名，核对与实际登录账号及签名内容一致。只有作者一致时才复用旧版外部配置。
- 在原 Best, 及本人姓名落款下追加当前作者确认的签名，不能替换原落款，也不能插入原作者或其他人的签名。
- 保留签名图片、链接和格式，避免重复插入及多余空行；不把 HTML 当纯文本发出。
- 发送前核对实际 To 地址、主题、正文与当前行一致，签名存在且图片加载完成。
- 图片在浏览器中可见不等于已上传完成。若客户端明确提示（如 Outlook 的 Please wait to send / Inline images are still loading），记录为尚未提交，关闭提示、等待上传完成，核对同一草稿后继续；不因此新建重复邮件。
- 点击发送后核对已发送邮件的实际收件地址、主题、正文与签名。只见编辑框关闭不能独立证明成功。
- 等待收件列表/阅读窗更新，不因短暂加载重新发送。发出后结果不明，先记为待核对并查已发送记录；无可靠结论时暂停该行，不自动重试。
- 遇登录失效、验证码、限流、发送拒绝或工具中断，停止受影响的发送并保存进度，不绕过限制。

## Excel 保存与断点

使用可用 spreadsheet skill；.csv 按 [user-setup](../draft-alumni-outreach/references/user-setup.md) 的「表格格式」写回。首次写回前在外部任务目录备份并记录源文件 SHA-256。

- 每封确认后先持久保存发送记录，包含作者 profile-id、实际发件账号、工作簿、sheet、行号、收件人姓名、地址、原稿指纹、时间、已发送记录链接/ID及本人签名核验结果。
- 每完成 5 人或约 3 分钟保存一次 Excel，以先到者为准；结束或中断前保存全部已确认结果。
- 写回前重新核对当前人员行、地址、内容、隐藏状态与源文件指纹。若外部修改，重新读取并按身份合并，不能用旧快照覆盖。
- 唯一常规值修改为已确认对应行的邮件/LinkedIn状态，以及获准新增的缺失状态列表头。保留其他内容、样式、公式、批注、超链接、筛选、隐藏行和其他 sheet。
- XLSX 库导出可能改写未涉及特性；必要时只合并授权单元格至原 ZIP，保持其他内部成员字节一致，并验证非目标单元格及样式不变。
- 不能安全写回时保留发送日志，明确“邮件已发送、Excel 待补标”，下次先核对补标，不能重发。
- 重试仅针对未发送且没有不明确发送尝试的行；不要把历史队列行号当作本次身份。

过程文件统一放在 `<根目录>/runs/<独立目录>/`（根目录见 user-setup，默认 `~/.alumni-outreach/`）。解析真实路径，所有备份、脚本、截图和临时工作簿放在源工作簿目录、skill 目录和 git 仓库之外。真实人员数据、签名图和发送日志不得保存到 skill 目录。

## 完成汇报

说明采用的当前作者和实际发件账号、sheet 和当前可见范围、本次确认发送数、已有发送跳过数、教育/校友和无邮箱跳过数、未解决或发送结果不明的数量、Excel 标记保存结果。LinkedIn 自动发送数应为 0；手动记录数量另列。

“发送成功”仅指发件客户端确认已发送，不承诺对方已收取、打开或邮箱始终可投递。提供原工作簿与必要的外部记录位置，按工具要求附发送凭证；不把未实际完成的结果写成完成。
