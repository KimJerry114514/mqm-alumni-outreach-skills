# 校友筛选与匹配

在写稿之前决定「找谁」，并为用户新建一张名单 sheet，后续写稿和发送都在这张 sheet 上进行。本 skill 不写稿、不发送、不访问 LinkedIn 主页。

## 交互顺序

按顺序问，已提供的信息不重复问（与 [user-setup](../draft-alumni-outreach/references/user-setup.md) 共用）：

1. **表格路径**（.xlsx 或 .csv）。.xlsx 读取后列出所有 sheet，请用户选择从哪个 sheet 里挑人。
2. **怎么挑人**：
   > 你已经在这个 sheet 里筛好要联系的人了吗？
   > A. 筛好了，直接用当前筛选结果
   > B. 还没有，请帮我挑
3. 选 **B** 时继续收集：
   - **你的简历**（PDF / DOCX / 文本路径，或直接上传）；
   - **你的 LinkedIn**（推荐）：自己主页 More → Save to PDF，或复制主页文字粘贴；只给网址时不自动抓取；
   - **你的偏好**，请用户用自己的话说一遍，例如：
     > 想找哪些地区的校友？（如 湾区、纽约、西雅图，或不限）
     > 想了解哪些行业或公司？（如 金融科技、咨询、某几家公司）
     > 想了解哪类岗位？（如 数据科学、BI、风控、咨询）
     > 对毕业年份有要求吗？（如 近五年）
     > 这轮想联系多少人？（默认 10）
   - 用户说「不确定」的项不强求；方向未说时，从简历提炼 2–3 个可能方向，各附简历依据，请用户选一个或多个。用户不选时不自行假定后继续。
4. 复述理解到的条件，例如「地区：CA/WA；行业：金融科技、支付；岗位：数据科学；2019 年以后毕业；10 人」，用户确认后开始挑选。

## A：用户已自行筛选

- 以所选 sheet 当前筛选后可见的有效人员行为名单，不重新排序、不删减、不改动原筛选。
- 只提示两类问题，由用户决定是否剔除：同一人重复出现、没有任何可用渠道。
- 用户不需要新 sheet 时，写稿 skill 直接在原 sheet 上工作；需要时按下文「新建名单 sheet」生成，「匹配理由」列留空。

## B：代为挑选

### 筛选

- 只在用户所选 sheet 的全部有效人员行中挑选（不限于当前可见行），除非用户要求只看可见行。
- 地区按 `Location` 当前部分匹配州缩写和城市；`(ex - ...)` 中的旧地点不算当前地点。
- 行业、公司、岗位按 `Employer` / `Title` 当前部分匹配；`(ex- ...)` 中的旧经历可作为匹配理由，但不当作现任。
- **不因表里已有的联系记录排除任何人**：原表的 `Sent Email`、`Sent LinkedIn`、`Coffee Chat`、行颜色等可能是别人的记录，与当前用户无关，挑选时一律忽略。每位用户只在自己的名单 sheet 里记录自己的联系。
- 身份冲突、同名不同人（例如同名的两行在不同公司）时，以「源行号 + LinkedIn 链接」区分，不能只按姓名匹配。
- 同一公司默认最多 2 人，避免名单集中；用户点名公司时不受此限。

### 排序与理由

只用表内事实（当前公司、职位、`ex-` 经历、地点、毕业年份、项目方向、昵称、渠道）和作者简历/LinkedIn 导出，不访问校友主页，不猜团队或项目。

| 维度 | 说明 |
| --- | --- |
| 方向契合 | 当前职位或公司属于用户选的方向；对方的转型路径（如 财务分析 → 数据科学）正是作者想走的路时视为强契合 |
| 经历连接 | 作者有一段能自然连到对方经历的真实经历（同行业、同类问题、同类工具）；只有专业相同不算 |
| 偏好匹配 | 地区、毕业年份等用户偏好 |
| 可联系性 | 有已核对的普通邮箱优先；教育/校友邮箱按写稿 skill 规则走 LinkedIn |

- 用「强 / 中」两档，不输出看似精确的分数。每人一句理由，能被表内字段或简历原文核对，例如「从 Deloitte 审计分析转到 Google 数据分析；你的会计数据分析专业和审计核对经历能直接连上」。
- `ex-` 列表中旧公司与旧职位的对应关系不明确时，理由里不要把某个旧职位断言为某家公司。
- 不因同名、同国籍、同姓推断共同点。
- 选出的人数比目标多约 50%，方便用户删减。
- **人数不够时**：如实告诉用户符合条件的人数，以及主要卡在哪一项（例如「湾区做金融科技数据科学的校友只有 9 人」）。给 2–3 个具体放宽方案让用户选，例如扩大地区、把 `ex-` 经历中的行业也算进来、放宽岗位类型。不要自行放宽条件。

## 新建名单 sheet

挑选完成后，为用户新建一张名单，后续写稿、发送都在这张名单上进行：

- **.xlsx**：在同一工作簿新建 sheet，默认名 `Shortlist <作者名或昵称> <MMDD>`（Excel sheet 名不超过 31 字符，重名时加序号）。
- **.csv**：在原文件同一目录新建 `<原文件名>-shortlist-<作者>-<MMDD>.csv`，编码和分隔符与原文件一致。
- 列：先复制原 sheet 中描述人员的原始列（姓名、昵称、邮箱、链接、公司、职位、地点、项目、年份等，表头与值原样）；**不复制**原表里的文案和联系状态列（如 `Email Content`、`LinkedIn Message`、`Sent Email`、`Sent LinkedIn`、`Coffee Chat`）及行颜色，这些可能属于别的作者。再在末尾追加：`Source Sheet`、`Source Row`、`Fit`（强/中）、`Match Reason`、`Keep?`（默认留空，用户填 N 表示剔除）、`Email Content`、`LinkedIn Message`、`Sent Email`、`Sent LinkedIn`。新 sheet 里这些文案和状态列一律从空白开始。
- 排序：强在前，组内按偏好匹配度。表头加粗冻结，`Match Reason` 自动换行。
- **不修改原 sheet**：不改其值、筛选、隐藏行、颜色、样式，不移动其他 sheet。.xlsx 写入遵循 [XLSX 保留与验证](../draft-alumni-outreach/references/xlsx-preservation.md)：只追加新 sheet 部件，原有部件保持一致；写前在外部任务目录备份。
- 源文件正被 Excel 等程序打开时，不强行写入：请用户先关闭文件；用户不便关闭时，写到工作簿副本并告诉用户位置。
- 同时在外部任务目录 `<根目录>/runs/<任务目录>/shortlist.json` 记录：源文件与 SHA-256、sheet、行号、LinkedIn 链接、Fit、理由、作者 profile-id、用户确认的条件。

## 确认与交接

1. 在对话中简要列出名单（姓名、当前公司/职位、地点、Fit、理由），并告诉用户新 sheet 的名字和位置。
2. 请用户在 `Keep?` 列标 N 剔除不想联系的人，或直接在对话中说「去掉第 3、7 个」。用户确认前不进入写稿。
3. **先看邮箱覆盖率**：统计保留下来的人里有多少人有已核对的普通邮箱。如果相当一部分人没有，或只有教育/校友邮箱，提示用户：可以先对这张名单 sheet 运行 `collect-alumni-emails` 补邮箱；否则这些人只会生成 LinkedIn 私信。由用户决定是否补。
4. 交接给 `draft-alumni-outreach`：工作表为新名单 sheet，范围为 `Keep?` 不为 N 的行；匹配理由作为写稿切入点参考。写稿前仍按实际行核对身份。
5. 发送阶段只按当前用户自己的名单 sheet 和本人发送日志去重，不参考原表或其他人的发送标记。

## 边界

- 名单只表示「建议联系」，不代表对方会回复、仍在该公司或邮箱可投递。
- 多位作者共用一份原始表时，每人各建自己的名单 sheet，不合并不同作者的选择或发送记录。
- 完成汇报：采用的方式（A 或 B）、确认的条件或方向、候选人数、排除数及原因、新 sheet 名称和位置，并明确「未写稿、未发送」。
