# 校友邀约文案

使用当前作者自己的简历事实（可选补充其本人 LinkedIn 导出），为用户指定的人员生成英文 coffee-chat 邮件与 LinkedIn 完整私信，沿用共用英文口吻，供用户审核，必要时写入现有 Excel。目标是提前建立关系、了解对方目前的工作与团队。招聘、面试、内推话题仅在本次用户明确要求时加入。

## 与邮箱收集的分工

- 挑选联系谁由 `match-alumni` 负责（可选）；本 skill 不替用户决定联系对象。
- 邮箱查找、归属核验和教育/校友类型标记由已有 `collect-alumni-emails` skill 负责。用户只要求写稿时，不重新收集或修改 Email 值。
- 本 skill 处理事实整理、个人化切入点、口吻拟合、批注修改、Excel 内容与阅读排版。
- 不发送邮件、LinkedIn 私信或连接申请，不创建邮箱草稿。此 skill 的调用本身不构成任何发送授权，也不把“已生成文案”写成“已发送”。

## 开始与范围

1. 读取本次实际工作簿（.xlsx 或 .csv），.xlsx 列出 sheet；.csv 视为单一 sheet。用户未指定 sheet 时询问；已明确指定则不重复问。不从旧任务推断 sheet、作者或行号。
2. 本轮已有 `match-alumni` 生成并经用户确认的名单 sheet 时，在该名单 sheet 上工作，范围为 `Keep?` 不为 N 的行，并把 `Match Reason` 作为切入点参考；仍按实际行重新核对身份。否则默认只处理所选 sheet 当前筛选后可见的有效人员行，不再询问处理范围。可见有效行很多（例如超过 30）且用户未说明是自己筛选的结果时，可一句话建议先用 `match-alumni`，用户拒绝则照常处理。按实际行隐藏状态核对，隐藏行不填写、不排版；不把历史可见人数或行号当作本次范围。如果没有筛选，则处理当前可见的有效人员行。用户本次明确要求全部人员、指定行或其他范围时，采用其要求。只有无法读取实际可见状态，或本次要求相互冲突时，才询问最小必要信息。
3. 读取实际表头，唯一定位姓名、Email、LinkedIn，以及 `Email Content`、`LinkedIn Message`。匹配忽略大小写与首尾空格；历史别名 `LinkedIn Content` 只在没有歧义时采用。
4. 用户说已新增列但磁盘文件仍读不到时，请其保存，重新读取；不要覆盖未保存编辑或擅自再加同名列。目标列缺失时，只有用户已授权新增才新增。
5. 检查已有内容和公式。默认只填目标空白格；只有本次要求修改、替换或应用批注时才改相应已有文案。既有公式不覆盖。
6. 为人员建立姓名、项目/年份、LinkedIn、原行指纹的映射。最终根据实际行重新核对，不只依赖历史行号。

## 首次使用与当前作者资料

先读[当前用户资料与首次使用](references/user-setup.md)，再读[共用英文口吻](references/voice-guide.md)。

- 写稿需要本人的简历附件或可读本地路径，以及表格路径和 sheet；本人 LinkedIn 导出（PDF 或粘贴文字）可选，用法见 user-setup。收集阶段已经确定的路径/sheet 不重复询问。可顺带问想了解的角色或方向，未提供则默认建立关系、了解对方工作。
- 从当前作者简历提取姓名、称呼、学校/项目、实际在读或毕业状态、毕业时间和相关经历。只补问影响正文且无法从文件唯一确定的信息，不要求重复手填整个简历。
- 每位作者的配置保存在 skill 目录之外的独立 `<根目录>/profiles/<profile-id>/profile.json`（根目录见 user-setup）；按上述指南核对归属。兼容旧版外部 profile.json 时也必须核对作者，换成别人的简历不能继续使用原作者的事实或批准记录。
- 共用口吻指南已匿名化并可随 skill 分发。其他人无需原作者的简历、私人 PDF 或本机路径；不能因这些文件不存在而阻止其使用本人简历写稿。
- 当前作者自有的样例、批注及已确认稿可进一步校准，但只复用属于该作者的事实。来源 PDF 含草稿、批注或历史版本时，不全部当作已发送定稿。
- 原始简历、真实联系人、原作者私人样例、签名和配置都不复制到 skill 目录。
- 不强制每个作者都是某校某项目学生、某专业出身或申请 Data Science；背景与目标从本人资料和本轮要求选择。毕业后不用 current student；只有年份时不补猜月份。
- 外部任务记录保存作者 profile-id、简历来源/指纹、事实出处和当前工作簿绑定。已有非空文案属于其他作者时，先核对归属，只在获准重写的范围内替换。
- 本轮明确的人物事实优先确定内容，最新风格要求优先确定表达；仅换简历时保留共用英文口吻。没有读过某份私人样例时，不声称已参考它。

## 选择填写渠道

按本轮用户确认的默认规则：

| Email 实际值 | Email Content | LinkedIn Message |
| --- | --- | --- |
| 格式合法的普通邮箱 | 填邮件主题及正文 | 同时填完整私信 |
| 教育邮箱、校友邮箱或对应文字标记 | 新任务空白格留空 | 填完整私信 |
| 无邮箱、非法地址、类型不明 | 新任务空白格留空，外部记录原因 | 身份足够明确时填完整私信 |

- 标记包括“教育邮箱”“校友邮件”“校友邮箱”；真实地址也检查完整域名，如学校 .edu / .edu.cn / .ac.uk、已确认学校域名和专用校友域名。
- 不把名字、状态文字、邮箱用户名或看似合法的地址当成已核验联系方式。
- 普通邮箱资格不意味着仍可投递；本轮不声称重新验证了历史邮箱。
- 两种文案都生成是备选渠道，不意味着同时联系同一人。
- 如果用户本次有不同的渠道规则，采用其明确规则。默认留空不授权清空已有 Email Content。

## 个人化与事实依据

每人先提炼一项有依据的职业兴趣，以及必要时一项真正的共同经历，再写稿。

- 优先关注目前做的工作、团队关注的问题、日常职责和数据如何用于决策。没有真实共同点时，直接写具体职业兴趣即可；只有双方资料证明同校时才提共同校友背景。
- 当前作者简历确有精算/保险背景时，才用于保险、定价、信用风险、量化分析等有实际关联的对象；不写“因为我学精算，所以我特别关注欺诈”之类没有解释的因果。
- 对 AI 或数据科学对象，可使用用户确实参与的相关项目或实习。区分参与和主导、原型和生产系统；不搬用对方项目的领域来夸大自己的经历。
- 姓名或昵称必须有明确关联；同名时需项目/年份、具体职业等独立线索确认。未解决身份冲突时留空并记录。
- 用可靠的较新记录修正草稿中的任职信息，不能因 sheet 用公司名命名就推断所有人的现任单位。不要为写稿顺手修改原 Employer、Title、姓名或链接列。
- 资料只支持过去任职时写 experience / earlier work，不断言现任。缺少细分团队信息时用开放问题，不编造项目、模型、客户或职责。
- 可以复用近期、与当前人员行匹配的核验记录；日志复用不等于本轮重新打开主页。明确保留来源日期和未刷新状态。
- 需要访问网页时复用已登录浏览器，只读取本次需要的信息，不重复查 Contact info 来写稿。遇限制、验证码或登录失效停止重复访问并保存进度；不尝试绕过或声称有保证安全的访问频率。
- 只有必要信息不足时补查。用户提供的主页文字、截图或 PDF 也可作为资料，不保证能获取完整主页。

## 写稿与复合审查

1. 先按样例写稿，再按用户批注修订，最后读一遍检查事实和自然程度；无需将中间版本都展示给用户。
2. Email Content 默认存为 `Subject: <subject>\n\n<完整正文>`。正文包括称呼、当前作者真实身份及相关背景、兴趣、简短邀约、本人落款；毕业信息仅在已知且适用时加入。
3. LinkedIn Message 是更短的完整私信，不是连接邀请短注；不能假称已经连接。用户要求邀请短注时另行遵守其明确用途。
4. 对同一作者已确认定稿的人员，核对归属后才原样复用；仅调整本轮明确修改的部分。换作者不得套用旧自我介绍，按其简历生成新稿并遵守覆盖范围。修改一处渠道的个人事实时核对另一渠道是否也需同步。
5. 做两轮不同检查：
   - **事实与对应检查**：当前作者姓名/称呼、本人简历事实及出处、实际学籍和毕业时间；收件人的当前/过去公司、真实共同点、邮箱资格、人员行与目标单元格。
   - **语言检查**：与共用口吻指南逐项对照；当前作者实际提供个人样例时再一并参考其开场、句长、缩写、兴趣表达、邀约和结尾；去掉空泛赞美、牵强联系和过多问题，保留用户本来常用的礼貌句。
6. 调用者要求 Humanizer 时优先读取可用版本；本机缺失可查找用户指定的公开版本。没有实际读取时不声称已使用。本 skill 自身不依赖额外 Humanizer 文件。
7. 风格评价给出具体相同点和残留差异，不声称“完全一致”、虚构拟合百分比或永久训练模型。
8. 不把内部注释、中文批注、来源说明、审核状态、收件人地址或 HTML 签名代码混进可发送正文。

## 落款与签名

- 保留资料文件或已确认原稿中的 `Best,` 和姓名落款，不能以“避免重复”为由自行删掉。
- Excel 中保存可复制的纯文字正文。用户保存的图文签名不擅自重做成文字或放进内容格。
- 若用户后续另行明确授权发送，保留原落款，再在下面追加已确认签名。正文批准、填表批准和测试发送都不等于向真实校友发送的批准。
- 图文发送能力以当前工具实际参数为准；纯文本连接器不能宣称能调用 Outlook 已保存签名或保留内嵌图片。独立 API 需要合法可用授权，不从浏览器或其他客户端提取凭据。

## Excel 保存与排版

.xlsx 写回前读取 [XLSX 保留与验证](references/xlsx-preservation.md)，使用可用的 spreadsheet skill 和其支持的工具；.csv 按 user-setup 的「表格格式」写回。

- 只改所选 sheet、所选范围、获准的两列内容；不改原 Email、姓名、公司、职位、链接、Sent Email 或 Coffee Chat。其他 sheet、隐藏行、公式、批注和超链接保留。
- 默认让目标文案列自动换行、左对齐、顶端对齐，调整这两列宽度与目标可见行高度，完整显示文字；沿用既有字体、颜色和边框，避免整张表统一重排。
- 用户本次要求只改值、格式不变或保留紧凑表格时，保留原排版，说明长文可在编辑栏查看。用户另行要求排版再调整。
- 不把隐藏行纳入填写或排版；不改筛选和行列顺序，不自动新增审核列、工作表、邮件主题列或状态标记。.csv 没有排版，只写值。
- 首次写入前在外部目录备份，记录指纹；定期保存进度。写回前后逐人对账并验证差异，只保留授权变化。
- 若发现外部修改，重新读取、按人员身份合并，不能用旧快照覆盖用户编辑。
