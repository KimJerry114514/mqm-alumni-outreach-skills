# XLSX 定向填写与保留

用于已有目录工作簿的两列文案写入和目标范围的换行排版。遵循可用 spreadsheet skill 的工具约束，不能因写稿而整体重建目录。

## 写前

- 解析源文件、任务目录真实路径，确认任务目录在工作簿目录之外。
- 备份当前实际文件，保存 SHA-256、sheet 名、表头、实际人员范围、行号、姓名/链接/项目年份、原行指纹和目标格原值。
- 核对两列唯一匹配，跳过既有非空文案和公式，除非此次明确要求修改。
- 排版前看当前列宽、行高、字体、边框、隐藏行和合并定义。Excel 的一条列宽定义可能同时覆盖 I:J；调整宽度要正确拆分区间，不能假设每列都有独立定义。

## 生成与保存

- 用支持的工作簿工具写入文字、设置获准的排版并渲染检查。
- 库整体重存可能改写非目标部件、字体元数据、扩展节点、筛选视图或共享字符串；导出成功不等于全部保留。
- 必要时以工具导出的目标内容为依据，仅把目标单元格写入原 XLSX ZIP。新字符串可以转为 inline string，保留原 sharedStrings 和非目标部件。
- 纯内容改动保留原单元格样式，只替换获准空白格的值。更改格式时从原样式复制，只改获准的 wrapText、对齐、行高和目标列宽，保留字体、颜色、边框和数字格式。
- 新样式追加，不能挪动原索引。所有未涉及 ZIP 成员应保持原字节；涉及成员应做到授权区域之外内容一致。
- XML 替换必须分别处理自闭合单元格和有结束标签的单元格，每个目标只匹配一个完整节点；不能吞掉相邻单元格。写后重新解析并逐格比对。
- 候选和临时文件留在外部任务目录；不在源工作簿所在目录创建临时 XLSX。写回前再次核对源指纹。出现外部修改时重读和合并，不能直接覆盖。

## 逐项验证

- 对当前工作簿重新读取的人员行与文案记录做一对一核对；重新验证表头、范围和隐藏状态。
- Email Content 符合本次邮箱规则；跳过不意味着清除原有内容。LinkedIn Message 数量与实际身份明确的目标人数一致。
- 校对主题、称呼、毕业年份、当前/过去任职、相关经历、落款，无批注或内部说明混入正文。
- 所有非目标值和公式一致；超链接、批注、表结构、筛选、行列顺序、隐藏行和其他 sheet 均保留。
- 原格式要求保留时逐格比较格式；仅授权排版时检查实际字体、颜色、边框保持一致，不只比较样式 ID。
- 渲染较长邮件、无邮件行和末尾记录等受影响范围，文字不跨列溢出、表头不截断，目标行高度足够。排版改变后的合并候选应重新打开渲染。
- 真正写回后再打开文件，核对内容、数量和差异审计。写回失败或差异越界，修复后再保存；无法保证时保留候选并报告，不覆盖原件。

正常完成仅表示文案已保存与对应关系检查通过，不表示已发信、已获收件人同意或已验证邮箱投递成功。
