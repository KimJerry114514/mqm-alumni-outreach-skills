# 当前用户资料与首次使用

三个 skill 共用这一份引导。用户用自然语言给信息即可，不要求手写配置、profile ID 或 JSON。按阶段收集，已提供或能从文件明确读出的信息不重复询问。

## 首次对话：按顺序收集

新用户第一次调用任何一个 skill（共四个：收集邮箱、筛选校友、写稿、发送）时，先用一条消息说明需要什么，然后按阶段收集。用户用自然语言回答即可；已提供或能从文件明确读出的信息不重复询问。

可直接这样开场（用用户的语言），一次问一步：

> **第 1 步**：请给我联系人表格的本地路径（.xlsx 或 .csv）。我读到后会列出所有 sheet，请你选一个。
>
> **第 2 步**：你已经在这个 sheet 里筛好要联系的人了吗？
> A. 筛好了，直接用当前筛选结果
> B. 还没有，请帮我挑
>
> **第 3 步**（两种情况都需要，写稿要用）：请给我你的简历；推荐再给你的 LinkedIn（自己主页 More → Save to PDF，或复制主页文字）。只给网址我不会自动抓取。
>
> **第 4 步**（选 B 时）：用你自己的话说说偏好：想找哪些地区、哪些行业或公司、哪类岗位的校友？对毕业年份有要求吗？这轮想联系多少人？不确定的可以跳过，我会根据你的简历给几个方向让你选。
>
> 我会从这个 sheet 里挑出合适的人，新建一个 sheet 给你，每人附一句匹配理由。你确认名单后我再写邮件和 LinkedIn 私信。发送前我还会问：用哪个学校 Outlook 邮箱发、要不要带你在 Outlook 里保存的签名（带签名会在 Outlook 网页里逐封发，较慢；不带就直接用连接器发），以及用来测试的你自己的邮箱。

| 阶段 | 必需信息 | 处理方式 |
| --- | --- | --- |
| 收集邮箱 | 表格本地路径；.xlsx 需选 sheet | 先检查路径并列出实际 sheet；用户已指定则直接采用。.csv 视为单一 sheet。默认仅当前筛选可见行（.csv 没有筛选，处理全部有效行或用户指定的行）。此阶段不需要简历、签名。 |
| 筛选校友 | 已筛好（A）或请 agent 挑（B）；选 B 时需简历、可选 LinkedIn、偏好 | 见 [match-alumni](../../match-alumni/SKILL.md)。A 直接用当前可见行；B 从所选 sheet 挑人并新建名单 sheet，名单须经用户确认。 |
| 写稿 | 本人简历；可选本人 LinkedIn 导出 | 复用本轮已确定的表格/sheet。事实优先级：本轮用户明确补充 > 简历 > 本人 LinkedIn 导出。LinkedIn 与简历冲突时（职位、日期、学校）以简历为准并提示用户。 |
| 写稿偏好 | 想了解的角色/方向或目的，可选 | 未提供时默认建立关系、了解对方工作；不凭原作者经历默认探索 Data Science、不默认求内推。 |
| 发送邮件 | 本人的发件账号（默认学校 Outlook 教育邮箱）、是否带 Outlook 已保存签名、测试收件地址、明确发送指令 | 带签名 → 浏览器操作已登录的 Outlook 网页逐封发；不带签名或纯文字签名 → 用本人账号的邮件连接器直接发。从实际登录账号和用户指定签名核对。测试收件地址由该用户本人指定；不沿用别人的邮箱或历史发送授权。 |

只问当前阶段缺少的必要信息。学校、项目、毕业时间或昵称能从简历唯一确认时直接整理；确有歧义且正文需要使用时再补问。发送账号和签名缺失不阻止前面的收集、写稿。

### 本人 LinkedIn 资料的用法

- 只用于补充简历没有写到的事实：英文昵称、近期职位变动、简介里写明的方向、证书。不把别人对其的推荐语、技能背书或点赞当作事实。
- 不访问、不抓取他人主页来了解作者本人；作者只给网址时，请其导出 PDF 或粘贴文字。
- 导出文件和粘贴内容视为个人资料，与简历一样只保存在下方的外部目录，不复制进 skill 目录或仓库。

### 表格格式

- .xlsx：按 [XLSX 保留与验证](xlsx-preservation.md) 写回，保留其他 sheet、样式、筛选和隐藏行。
- .csv：先检测编码（UTF-8 / UTF-8-BOM / GBK）和分隔符，按原编码、原分隔符、原换行写回；只新增或填写获准的 `Email Content`、`LinkedIn Message`、`Sent Email`、`Sent LinkedIn` 列，其余列和行顺序不变。CSV 单元格内的换行必须用双引号包裹。写回前在外部目录备份原文件。
- 项目同学共用同一份原始表格时，每人先复制一份自己的工作副本再使用，避免多个作者的文案和发送标记写进同一个文件。

## 作者事实与共用风格

- 当前作者由本轮明确指定的人和简历确定。换成别人的简历，即使仍在同一台电脑、同一个系统用户、同一个聊天中，也要按另一位作者处理。
- 姓名、英文称呼、学校、项目、在读/毕业状态、毕业时间、专业、实习、公司、项目、技能及职业目的均来自当前作者简历或本轮明确补充。日期按当前时间检查；简历只写年份时不补猜月份。
- 简历未证明的身份和经历不写；不把模板、原作者样例、旧日志或收件人的经历当作当前作者事实。
- 收件人来自某校校友目录不代表当前作者毕业于该校。只有双方资料支持时才写同校、同项目、同专业。
- 共用语言风格见 [voice-guide.md](voice-guide.md)：沿用原作者已确认的开场、句长、兴趣表达、邀约和结尾。换简历只更换事实及相关切入点，不自动改换口吻。
- 共享指南已提炼并匿名化，无需原作者简历、原始私人 PDF 或联系方式。当前用户提供的个人简历和补充优先确定事实；明确的新风格要求仍按其本轮指令执行。
- 每项发件人事实在外部任务记录关联简历页码/段落或本轮补充。声称“学过、做过、主导、部署”等时核对原文程度。
- 写稿前给简短的已读事实摘要，例如姓名、当前身份、毕业时间、相关经历。明确的事实不强制逐项确认；矛盾或含糊的关键事实先问清，其他工作可继续。

## 每位作者独立配置

配置和真实个人资料不放进 skill 目录。

- 根目录：环境变量 `ALUMNI_OUTREACH_HOME` 指定的目录；未设置时用 `~/.alumni-outreach/`（Windows：`%USERPROFILE%\.alumni-outreach\`）。
- 兼容旧位置：`~/Library/Application Support/Codex/alumni-outreach/`、`~/.local/state/codex/alumni-outreach/` 存在时可读取，但同样先核对作者归属。
- 任务过程文件放在根目录下的 `runs/<日期-时间-sheet-用途>/`。
- 每位作者使用 profiles/<profile-id>/profile.json，profile-id 自动生成；人物姓名、简历路径/指纹、事实与出处、个人偏好、发件账号和签名设置随本人保存。
- 不因目录存在、系统用户名相同或文件名叫 profile.json 就默认属于当前作者。读取旧配置前核对 owner/author 姓名及本轮简历人物；资料冲突时以明确的新输入为准，不能混合两个人的经历。
- 兼容根目录旧版 profile.json：只有作者已核对一致时才复用。不同作者另建配置，保留原作者配置，不覆盖、不复制其默认学校、姓名、邮箱、签名、测试地址或授权。
- 每次任务记录采用的 profile-id、简历来源及指纹、事实摘要、工作簿真实路径和 sheet。收集阶段可暂不绑定作者，写稿/发送前必须绑定。
- 原作者可继续使用其原简历、私有样例和已确认文案；这些仅属于该作者，不是分发包的必需文件。

外部配置的建议字段（由 agent 填写，不要求用户输入 JSON）：
profile_id；author（full_name、preferred_name、school、program、status、graduation）；
sources（resume、resume_sha256、linkedin_export、linkedin_export_sha256、optional_personal_examples）；
facts（事实、来源及核实状态）；preferences（purpose、subject、email_signoff、shared_voice）；
mail（from_address、signature_mode：outlook_saved / plain_text / none、signature_text 或 Outlook 签名名称）；workbooks（路径、sheet、文案作者）。

缺失信息可留空或省略，不创建虚构默认值；密码、access token 不保存到这些配置。

## 工作簿与发送记录的归属

- 相同联系人可以出现在不同作者的工作簿中。旧文案里的自我介绍和旧 Sent Email/Sent LinkedIn 标记，不自动代表新作者的文案或发送历史。
- 切换作者而工作簿含非空文案或发送标记时，先核对它们属于谁；不能直接把旧文案署名换成新作者后发送，也不清空旧标记。
- 已有文案与当前作者不一致时，发送阶段暂停这部分并回到写稿阶段；仅在用户已授权重写对应范围时覆盖旧稿。仅提供新简历不等于授权覆盖所有已有内容。
- 作者归属不清、又影响记录或发送时，只补问这一项；可以建议独立副本，但不擅自复制工作簿或新增每人一套列。新工作簿没有此冲突时无需增加询问。
- 跨 sheet/日志去重需核对发件人归属；不能把另一作者的发送记录当成本人已发。当前用户若明确要求避免不同作者重复联系同一人，遵从其范围。
- 填写文案、给用户测试发信、旧作者批准均不授权新作者正式发送。已在本轮明确批准的同一作者、内容和范围不重复索要许可。
